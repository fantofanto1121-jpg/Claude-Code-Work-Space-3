# セキュリティ対策の一覧

実装済みの対策と、**実装していない／運用でカバーすべきこと**を正直に書いています。

---

## 1. 実装済みの対策

### SQLインジェクション

**対策**: SQLAlchemy ORM を使い、SQL文を文字列で組み立てていません。
値は必ずパラメータとして渡されます。

検索の `ILIKE` では、ワイルドカード（`%` `_`）とエスケープ文字を無害化しています
（`app/services.py` の `_escape_like()`）。

**検証**: `tests/test_security.py::test_sql_injection_in_search_is_harmless` ほか5件

### XSS（クロスサイトスクリプティング）

**対策**: 3重にしています。

1. Jinja2 の自動エスケープを有効化（`app/templating.py`）
2. 投稿本文は `app/utils.py` の `render_body()` で、URLと `>>番号` 以外の
   すべての文字を `escape()` してから組み立て。`<script>` を書かれても文字として表示されます
3. CSP ヘッダーで `script-src 'self'` を指定。外部スクリプトもインラインスクリプトも実行されません

リンク化するのは `http://` と `https://` のみです。`javascript:` はリンクになりません。
生成するリンクには `rel="nofollow noopener noreferrer"` を付けています。

**検証**: `test_script_in_post_body_is_escaped`（6パターン）、`test_render_body_unit` ほか

### CSRF（クロスサイトリクエストフォージェリ）

**対策**: 2重にしています。

1. セッションCookieに `SameSite=Lax` を設定（他サイトからのPOSTにCookieが付かない）
2. 署名付きトークンの二重送信。全POSTで `verify_csrf` を通し、
   Cookieの値とフォームの値を定数時間比較（`hmac.compare_digest`）

**検証**: `test_post_without_csrf_token_is_rejected` ほか4件

### パスワードの管理

| 項目 | 内容 |
|------|------|
| ハッシュ方式 | **Argon2id**（`argon2-cffi`） |
| パラメータ | time_cost=2, memory_cost=19MiB, parallelism=1 |
| 平文保存 | **しない** |
| ログ出力 | **しない** |
| 最低文字数 | 10文字 |
| 単純なパスワード | 英字のみ・数字のみを拒否 |
| 変更時 | `session_version` を +1 して全端末を強制ログアウト |

### セッション管理

- `itsdangerous` による署名付きCookie。改ざんすると検証に失敗します
- Cookie属性: `HttpOnly`（JSから読めない）、`SameSite=Lax`、本番では `Secure`
- 有効期間 30日
- `users.session_version` と照合。パスワード変更・退会・BAN時に +1 して既存セッションを無効化

### 認証と権限チェック

**管理者判定は必ずサーバー側で行います。**

```
Cookieの署名を検証 → DBからユーザーを取り直す → user.role を見る
```

リクエストに `role=admin` を混ぜても効きません（`test_role_cannot_be_elevated_from_the_request` で検証）。

管理者になれるのは、環境変数 `ADMIN_EMAILS` に登録されたアドレスのみです。
`ADMIN_EMAILS` から外すと、次回ログイン時に自動的に一般ユーザーへ戻ります。

| 操作 | 必要な権限 |
|------|-----------|
| 閲覧・検索 | 不要 |
| スレッド作成・返信 | ログイン＋BANされていない＋（設定時）メール確認済み |
| 投稿の削除 | **本人** または管理者 |
| 管理画面 | 管理者のみ |

**検証**: `tests/test_permissions.py`（12件）。特に
`test_user_cannot_delete_another_users_post` で「他人の投稿を消せない」ことを確認しています。

### サーバー側の入力検証

ブラウザ側の `maxlength` や `required` は**補助**であり、信用していません。
すべて `app/services.py` でサーバー側に再検証を置いています。

| 項目 | 制限 |
|------|------|
| スレッドタイトル | 2〜80文字、制御文字と不可視文字を除去 |
| 本文 | 1〜4000文字、60行まで、改行とタブ以外の制御文字を除去 |
| 表示名 | 1〜24文字、予約語（運営・admin等）は拒否 |
| メールアドレス | 形式チェック、254文字以内、小文字に正規化 |

### レート制限

`rate_limit_hits` テーブルで記録します（再起動しても引き継がれます）。

| 対象 | 制限 |
|------|------|
| ログイン試行（IP単位） | 15分に20回 |
| ログイン試行（アカウント単位） | 15分に8回 |
| 新規登録（IP単位） | 1時間に5回 |
| パスワード再設定 | 1時間に5回 |
| スレッド作成 | 1時間に5回 |
| 投稿 | 10分に15回 |
| **連続投稿の間隔** | **15秒に1回** |
| 通報 | 1時間に10回 |
| 検索 | 1分に60回 |

加えて、同じ本文を10分以内に再投稿することを禁止しています（コピペ連投対策）。

### アカウントの存在を推測させない

- ログイン失敗時のメッセージは、アドレス誤り／パスワード誤りで**同一**
- 存在しないアカウントでも、同じ計算時間がかかるようダミーのハッシュ計算を実行
- パスワード再設定は、登録の有無にかかわらず同じ画面を表示

> **例外**: 新規登録時のみ「すでに登録されています」と表示します。
> これは、利用者が登録済みと気づけないと詰んでしまうためです。
> アカウント存在の推測を完全に防ぎたい場合は、`app/routers/auth.py` の
> `register()` を「確認メールを送った」とだけ表示する方式に変更してください
> （その場合、メール送信の設定が必須になります）。

### セキュリティヘッダー

全レスポンスに付与しています（`app/main.py`）。

| ヘッダー | 値 |
|----------|-----|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self'; frame-ancestors 'none'` ほか |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | 位置情報・マイク・カメラを無効化 |
| `Strict-Transport-Security` | 本番のみ。1年間HTTPS強制 |

### その他

| 項目 | 対策 |
|------|------|
| オープンリダイレクト | `safe_next_path()` で `/` 始まりの内部パスのみ許可 |
| APIドキュメントの露出 | `/docs` `/redoc` `/openapi.json` を無効化 |
| エラー画面からの情報漏洩 | 内部例外はログにのみ記録し、画面には定型文を表示 |
| ログへの機密情報記録 | パスワード・セッショントークンを記録しない |
| 秘密情報の管理 | すべて環境変数。`.env` は `.gitignore` 済み |
| 通信の暗号化 | Render が標準でHTTPSを提供。本番では Cookie に `Secure` 属性 |
| トークンの保存 | パスワード再設定トークンは SHA-256 ハッシュで保存（生の値は保存しない） |

## 2. 実装していないこと（把握しておくべき限界）

| 項目 | 状況 | 必要になったら |
|------|------|----------------|
| 2段階認証（2FA） | 未実装 | 利用者が増えたら検討 |
| CAPTCHA | 未実装 | 大量のbot登録が起きたら Cloudflare Turnstile 等を検討 |
| IPアドレスの長期保存 | していない | 発信者情報開示に備える場合、保存方針を専門家と検討してください |
| 画像アップロード | 未実装 | 追加する場合、ファイル形式検証・容量制限・外部ストレージが必須 |
| WAF | 未導入 | Cloudflare を前段に置く方法があります |
| 監査ログの外部保存 | DB内のみ | 重要度が上がれば外部転送を検討 |
| 依存ライブラリの脆弱性監視 | 未設定 | GitHub の Dependabot を有効にすることを推奨 |

### メール確認について

既定では `REQUIRE_EMAIL_VERIFICATION=false` です（メール設定なしでも動くようにするため）。
**公開運営する場合は `true` にすることを強く推奨します。**
捨てアドレスによる大量登録を抑制できます（ただし Resend の設定が必要です）。

## 3. 運用上の注意

1. **`SECRET_KEY` を変更しない。** 変更すると全ユーザーがログアウトされます
2. **`.env` を絶対にコミットしない。** `git status` で毎回確認する習慣を
3. **`ADMIN_EMAILS` は最小限に。** 管理者は投稿の削除とBANができます
4. **依存ライブラリを定期的に更新する。** `pip list --outdated` で確認
5. **公開前に `pytest` を実行する。** 83件すべてが通ることを確認
6. **`rate_limit_hits` を定期的に掃除する。** `app/ratelimit.py` の `prune()`
