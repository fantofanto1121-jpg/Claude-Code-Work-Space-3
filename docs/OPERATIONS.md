## 2. 法律面で検討すべきこと

いずれも**専門家の確認が必要**です。ここに書いたことを法的助言として扱わないでください。

### (a) 発信者情報開示への備え

日本では、掲示板の投稿で権利を侵害されたとする人から、
**発信者情報開示請求**を受ける可能性があります。
関係する法律はプロバイダ責任制限法（および情報流通プラットフォーム対処法など
関連する法改正）です。

検討すべき点:

- 開示請求に対応できる**連絡窓口**を明示しているか（`/contact` ページ）
- **アクセスログ（IPアドレス・タイムスタンプ）をどれだけ保存するか**
  - 現在の実装では、IPは `rate_limit_hits` に短期間しか残りません
  - 開示請求に応じられる体制が必要かどうかは、専門家に確認してください
  - 保存するなら、プライバシーポリシーに保存期間を明記する必要があります
- 請求を受けたときの**判断手順**を事前に決めているか

> **この項目は実装で完結しません。** 運営体制の問題です。

### (b) 権利侵害の申告への対応

- 削除依頼の受付方法を `/contact` に記載済み（連絡先の記入が必要）
- 申告を受けてから対応するまでの**目安日数**を決めておく
- 明らかな権利侵害と、意見の対立の**切り分け方針**を決めておく

### (c) 個人情報保護法

- 取得する情報と利用目的をプライバシーポリシーに記載済み（要記入）
- 保有個人データの**開示・訂正・削除請求への対応手順**を整備する
- 外部サービス（Render / Neon / Resend）へのデータ保管を記載済み（事業者名の記入が必要）

### (d) 特定商取引法

無料サービスで収益がない間は通常は不要ですが、
**有料機能を追加する場合は表示義務が生じます**。導入前に確認してください。

### (e) その他

| 項目 | 検討事項 |
|------|----------|
| 青少年保護 | 年齢確認を行うか。わいせつ表現への対応方針 |
| 著作権 | 無断転載への対応手順 |
| 広告 | 景品表示法、ステマ規制（2023年10月〜）への対応 |
| 海外からの利用 | GDPR等が関係するか（日本国内限定なら通常は不要） |

## 3. 日常の運営

### 毎日〜数日に1回

1. 管理画面（`/admin`）を開く
2. **未対応の通報**があれば確認する
3. 対応を決める

| 通報内容 | 対応の目安 |
|----------|-----------|
| スパム・宣伝 | 投稿を非表示 → 繰り返すならBAN |
| 誹謗中傷 | 内容を読んで判断。明確な攻撃なら非表示 |
| 個人情報 | **最優先で非表示**。被害が拡大する前に |
| 違法・権利侵害 | 非表示にしたうえで、記録を残す |
| 意見の対立 | 原則として非表示にしない（「却下」を選ぶ） |

### 管理操作はすべて記録されます

誰がいつ何をしたかは `/admin/logs` で確認できます。
後から「なぜこの投稿を消したのか」を説明できるよう、
操作時の**備考欄に理由を書く習慣**をつけてください。

### 週1回

- [ ] `bash scripts/backup.sh` でバックアップ
- [ ] Render / Neon の使用量を確認（無料枠に収まっているか）

### 月1回

- [ ] バックアップから復元できるか試す
- [ ] `pip list --outdated` でライブラリの更新を確認
- [ ] `rate_limit_hits` の掃除（[BACKUP.md](BACKUP.md) 末尾）

## 4. 荒らしへの対処

段階的に対応してください。

1. **投稿を非表示**（`/admin/reports` または投稿の「管理: 非表示」）
2. **スレッドをロック**（`/admin/threads` → ロック）— 返信だけ止められます
3. **利用者を期間制限**（`/admin/users` → 1日/7日/30日/無期限）
4. 悪質な場合は無期限BAN

> BANすると `session_version` が +1 され、**即座に全端末からログアウト**されます。

### 大量のアカウント作成が起きたら

1. `REQUIRE_EMAIL_VERIFICATION=true` にする（最も効果的）
2. `app/ratelimit.py` の `register_ip` の制限を厳しくする
3. それでも収まらなければ、Cloudflare Turnstile などのCAPTCHA導入を検討

## 5. 収益化を追加するとき

現在の設計は、あとから収益化を足せるようになっています。

### (a) 広告

**変更が必要な箇所:**

1. `app/templates/base.html` に広告枠を追加
2. **`app/main.py` の CSP ヘッダーを緩める必要があります**

   ```python
   # 広告スクリプトを読み込むため、配信元ドメインを許可する
   "script-src 'self' https://pagead2.googlesyndication.com; "
   "img-src 'self' data: https:; "
   ```

   > CSP を緩めると XSS への耐性が下がります。許可するドメインは最小限にしてください。

3. プライバシーポリシーに、広告配信事業者とCookie利用を追記（必須）
4. 各広告サービスの審査基準を満たすか確認（掲示板は審査が厳しい傾向があります）

### (b) 寄付

最も手軽で、法的な手続きも最小です。

- フッターに外部サービス（Buy Me a Coffee 等）へのリンクを置くだけ
- プライバシーポリシーへの追記は通常不要（外部リンクのため）

### (c) 有料機能（サポーター制度）

**設計上の準備:** `users.role` が既に拡張可能です（`user` / `admin`）。
`supporter` を追加し、`deps.py` に `require_supporter` を作れば実装できます。

アイデア: 広告非表示、表示名の装飾、スレッドのお気に入り上限アップなど

**追加で必要になること:**

- 決済サービス（Stripe 等）の導入
- **特定商取引法に基づく表示**（必須）
- 利用規約への課金条項の追加
- 返金・解約ポリシー
- 会計処理

> 有料化は法務・税務の負担が一気に増えます。
> まずは**寄付リンク**から始めるのが現実的です。
